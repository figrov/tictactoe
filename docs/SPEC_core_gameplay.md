# Спецификация фичи: Core Gameplay 3×3 (PvP)

## 1. Цель и концепция фичи

**Цель:** Реализовать классические крестики-нолики 3×3 для двух игроков на одном экране. Это базовая игровая механика, лежащая в основе всего продукта.

**Ценность для игрока:** Простой, интуитивно понятный, но азартный PvP-матч с мгновенным возобновлением после завершения раунда. Накопленный счет побуждает возвращаться к игре.

**Связь с Core Loop:** Первое взаимодействие с игрой — заполнение поля, фиксация победителя/ничьи и мгновенный рестарт. Этот Core Loop станет ядром всех последующих режимов (ИИ, сетевая игра).

## 2. Игровая логика и State Machine

### 2.1 Состояния игры (Finite State Machine)

```
┌─────────────────────────────────────────────────────────────────┐
│                    GAME_STATE (Enum)                            │
├─────────────────────────────────────────────────────────────────┤
│  IDLE          - экран приветствия, "Начать игру"                │
│  PLAYING       - активная партия, клики по клеткам                │
│  GAME_OVER     - победа/ничья, линия победы видна                 │
│  PAUSED        - пауза (не используется в MVP, но в архитектуре) │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 Внутреннее состояние (Game Board)

```kotlin
data class GameBoard(
    val cells: List<CellState> = List(9) { Empty },
    val currentPlayer: Player = Player.X,
    val scoreX: Int = 0,
    val scoreO: Int = 0,
    val drawCount: Int = 0,
    val isWinningCells: List<Int>? = null,  // список индексов клеток с выигрышем
    val winner: Player? = null
)

enum class CellState { Empty, X, O }
enum class Player { X, O }
```

### 2.3 Правила переходов состояний

| Текущее состояние | Событие | Новое состояние | Условия |
|-------------------|---------|-----------------|---------|
| IDLE              | `startGame()` | PLAYING | Кнопка "Начать" нажата |
| PLAYING           | `cellClicked(index)` | PLAYING | Клетка пуста → клетка отмечена → проверка победы/ничьи |
| PLAYING           | `cellClicked(index)` | GAME_OVER | Победитель найден → отображается линия победы |
| PLAYING           | `gameOver()` | PLAYING | Победитель/ничья → ход переходит к следующему раунду (счет сохраняется) |
| GAME_OVER         | `newRound()` | PLAYING | Кнопка "Продолжить" нажата → поле очищается, currentPlayer сбрасывается |
| GAME_OVER         | `newGame()` | IDLE | Кнопка "Новая игра" нажата → поле очищается, счет сбрасывается |

### 2.4 Правила победы и ничьей

**Победа:** 3 одинаковых символа в любом направлении:
- Горизонталь: (0,1,2), (3,4,5), (6,7,8)
- Вертикаль: (0,3,6), (1,4,7), (2,5,8)
- Диагональ: (0,4,8), (2,4,6)

**Ничья:** Все 9 клеток заполнены И отсутствует победитель.

**Взаимное исключение:** Если есть победитель — ничья не фиксируется (по умолчанию в правилах Крестики-нолики, но допустимо реализовать правило "победа перекрывает ничью").

## 4. Граничные случаи (Edge Cases)

### 4.1 Spam Protection (Multi-touch / Double-click)

**Проблема:** Двойной клик по одной клетке или быстрые клики до завершения анимации приведут к двум пометкам.

**Решение:**
- Добавить флаг `isCellAnimating(index) = true` при клике.
- Игнорировать клики, пока `isCellAnimating = true`.
- Обновлять флаг через `delay(200ms)` после начала анимации.
- В UI слой: `if (isCellAnimating) return` в обработчике `onClick`.

### 4.2 Поворот экрана и пересоздание Activity

**Проблема:** При повороте Compose recompose и может потеряться состояние поля (если не использовать `rememberSaveable`).

**Решение:**
- Использовать `LaunchedEffect(key1 = Unit) { state = boardState.toUiState() }` и сохранять `UiState` в `SavedStateHandle` через `rememberSaveable`.
- В `MainActivity`:
  ```kotlin
  val uiState = viewModel.uiState.collectAsState()
  LaunchedEffect(Unit) {
      if (savedStateHandle.get<String>("uiStateJson") != null) {
          // восстановить состояние
      }
  }
  ```

### 4.3 Сворачивание/разворачивание приложения

**Проблема:** После сворачивания приложения состояние должно сохраняться (Android lifecycle).

**Решение:**
- Использовать `SavedStateHandle` для сохранения состояния игры (Json-строка `UiState`).
- Добавить сохранение перед onPause и восстановление после onCreate.
- Проверка: при восстановлении `if (uiState != null) { boardState = uiState.toBoardState() }`.

### 4.4 Много-клики по клеткам после завершения раунда

**Проблема:** После победы/ничьи игрок может случайно кликать по занятым клеткам.

**Решение:**
- В состоянии `GAME_OVER` и `PLAYING` после завершения раунда:
  - Поле заблокировано (добавить флаг `isBoardLocked = true`).
  - `onClick` проверяет `if (isBoardLocked || cells[index].isMarked()) return`.

### 4.5 Быстрый клик по "Новая игра" при заполнении поля

**Проблема:** Игрок может дважды кликнуть по кнопке и запустить новый раунд до завершения текущего.

**Решение:**
- Добавить флаг `isButtonAnimating = true` при клике.
- Блокировать клики до `delay(200ms)`.
- Использовать `animateClick` на кнопке: `Modifier.clickable(enabled = !isButtonAnimating)`.

### 4.6 Игнорирование кликов по кнопкам при анимации линии победы

**Проблема:** Игрок может кликать по кнопкам до завершения анимации линии победы.

**Решение:**
- В состоянии `GAME_OVER` флаг `isGameOverAnimating = true`.
- Кнопки блокируются: `Modifier.clickable(enabled = !isGameOverAnimating)`.

## 5. Критерии приемки (Acceptance Criteria)

### AC-01: Запуск игры из экрана приветствия
**Given** пользователь находится на экране IDLE
**When** нажимает кнопку "Начать игру"
**Then** экран переключается на PLAYING, поле очищается, ход переходит к X

### AC-02: Отображение текущего хода
**Given** игра находится в состоянии PLAYING
**When** игрок X сделал ход
**Then** отображается "Ход: X"
**When** игрок O сделал ход
**Then** отображается "Ход: O"

### AC-03: Проверка победы при X
**Given** на поле расставлены X в ряд (0,1,2)
**When** игрок кликает на клетку 2
**Then** игра переходит в GAME_OVER, отображается "Победил X!", line victory на клетках 0-1-2

### AC-04: Проверка победы при O
**Given** на поле расставлены O в ряд (3,4,5)
**When** игрок кликает на клетку 5
**Then** игра переходит в GAME_OVER, отображается "Победил O!", line victory на клетках 3-4-5

### AC-05: Проверка победы по вертикали
**Given** на поле расставлены X в вертикальном ряду (0,3,6)
**When** игрок кликает на клетку 6
**Then** фиксируется победа X, отображается линия victory на клетках 0-3-6

### AC-06: Проверка победы по диагонали
**Given** на поле расставлены O в диагональном ряду (0,4,8)
**When** игрок кликает на клетку 8
**Then** фиксируется победа O, отображается линия victory на клетках 0-4-8

### AC-07: Фиксация ничьи
**Given** все 9 клеток заполнены, победителя нет
**When** последний клик был по свободной клетке
**Then** игра переходит в GAME_OVER, отображается "Ничья!"

### AC-08: Счетчик побед и ничьих
**Given** X выиграл партию (AC-03)
**When** игрок нажимает "Продолжить"
**Then** счет X увеличивается на 1
**Given** зафиксирована ничья (AC-07)
**When** игрок нажимает "Продолжить"
**Then** счет ничьих увеличивается на 1

### AC-09: Игнорирование клика по занятой клетке
**Given** клетка уже отмечена (X или O)
**When** игрок нажимает на эту клетку
**Then** никакой реакции, ход не переходит, анимация не проигрывается

### AC-10: Двойной клик по одной клетке
**Given** клетка пуста
**When** игрок делает двойной клик на эту клетку за 300ms
**Then** клетка помечается только один раз, второе нажатие игнорируется

### AC-11: Повторное нажатие на занятую клетку после завершения раунда
**Given** раунд завершен (X выиграл)
**When** игрок нажимает на занятую клетку
**Then** никакой реакции, клетка не меняется, счет не обновляется

### AC-12: Кнопка "Новая игра" при заполненном поле
**Given** поле заполнено, ничья зафиксирована (AC-07)
**When** игрок нажимает "Новая игра"
**Then** поле очищается, счет сбрасывается, экран возвращается в IDLE

### AC-13: Кнопка "Новая игра" при наличии счета
**Given** X: 1 | O: 0 | Draw: 0, X выиграл партию
**When** игрок нажимает "Новая игра"
**Then** поле очищается, счет сбрасывается до 0:0:0, экран IDLE

### AC-14: Анимация появления символа
**Given** на пустую клетку нажали
**When** отображается X или O
**Then** символ появляется с scale 0 → 1, opacity 0 → 1 за 200ms

### AC-15: Сохранение состояния при повороте экрана
**Given** игра в PLAYING, счет X: 1, X только что сделал ход
**When** пользователь поворачивает экран на 180°
**Then** состояние восстанавливается (X: 1), ход переходит к O, поле сохранено

## 6. План реализации (Sub-tasks)

### Sub-task 1: Domain Layer (логика и State Machine)
- Создать классы `GameBoard`, `CellState`, `Player`, `GameState` в пакете `domain`.
- Реализовать метод `checkWin(cells: List<CellState>): Pair<Boolean, List<Int>?>` для проверки победы.
- Реализовать метод `checkDraw(cells: List<CellState>): Boolean` для проверки ничьи.
- Реализовать метод `makeMove(index: Int): GameBoard` с валидацией (клетка пуста) и проверкой победы.
- Добавить тесты: `checkWin` для всех 8 возможных комбинаций, `checkDraw` на 9 заполненных клетках, `makeMove` с повторными кликами.

### Sub-task 2: Presentation Layer (ViewModel и UiState)
- Создать `GameViewModel` в пакете `presentation`.
- Использовать `StateFlow<GameBoard>` для хранения состояния.
- Реализовать `UiState` класс с `UiEffect` (click, ignore, success, info).
- Реализовать событийные потоки: `Intent`, `Event`, `SideEffect`.
- Добавить `LaunchedEffect` для обработки изменения состояния и обновления `UiState`.
- Тесты: `play` действие, проверка победы, проверка ничьи, сохранение состояния.

### Sub-task 3: UI Layer (Compose и Canvas)
- Создать `TicTacToeScreen` в пакете `ui`.
- Реализовать экран приветствия с кнопкой "Начать игру".
- Реализовать основной экран с Canvas-сеткой, 9 клеток и кнопками.
- Добавить анимации появления символов (`AnimatedVisibility` + `scaleIn`).
- Реализовать отрисовку линии победы (Canvas `drawLine`).
- Добавить семантические теги для тестирования (Compose UI Test).
- Тесты: визуальное отображение сетки, анимации, проверка testTag.

### Sub-task 4: Сохранение состояния и Edge Cases
- Интегрировать `SavedStateHandle` для сохранения состояния при повороте экрана.
- Добавить логику блокировки поля после завершения раунда (`isBoardLocked`).
- Добавить спам-протекцию (delay 200ms после клика).
- Тесты: поворот экрана, сворачивание приложения, двойной клик, повторный клик после завершения.

## 7. Связи с другими фичами

- **FEAT-02 (ИИ-соперник):** Логика проверки победы и ничьей переиспользуется. Игрок O будет заменен на ИИ в будущем.
- **FEAT-03 (История партий):** Счет побед/ничьих будет сохранен в `SharedPreferences` или Room для использования в статистике.
- **FEAT-04 (Звук и вибро):** UiEffect триггеры будут интегрированы сMediaPlayer и Vibrator.
